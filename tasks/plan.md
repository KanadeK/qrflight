# Implementation plan: QRFlight v0.1.0

## Overview

Deliver the smallest complete path from untrusted QR raster to evidence-backed print-readiness
report, then package and publish the exact verified commit. Risk is front-loaded: prove two real
decoders and physical geometry before adding report surfaces.

## Architecture decisions

- Validated image, decoder, scenario and report models form contracts between modules.
- Decoder adapters are independent and return data; the engine owns reconciliation and severity.
- Transformations are deterministic pure functions parameterized in physical or explainable units.
- Reports consume a single versioned model so text, JSON and HTML cannot disagree.

## Dependency graph

```text
bounded loader -> decoder adapters -> baseline reconciliation -> static metrics
                                             |                    |
                                             +-> transformations <-+
                                                        |
                                                  versioned report
                                                   /     |     \
                                                text   JSON   HTML
```

## Phases

### Phase 1: Proven core

- Task 1: define contracts and generate real deterministic fixtures.
- Task 2: load safely and cross-decode a baseline QR.
- Task 3: measure static geometry and physical print signals.

Checkpoint: healthy/cropped/hostile fixtures have focused red-to-green tests and both real
decoders agree on the healthy payload.

### Phase 2: Failure boundary

- Task 4: implement deterministic degradation families and profiles.
- Task 5: reconcile scenario results into explicit findings and thresholds.
- Task 6: serialize versioned JSON and text.

Checkpoint: every scenario writes a real transformed image in tests, gets decoded, and two
identical runs produce byte-identical JSON.

### Phase 3: Complete user workflow

- Task 7: add offline HTML evidence and CLI exit semantics.
- Task 8: add committed examples and visual evidence generated by the real engine.
- Task 9: document acceptance, repair, threat model and architecture.

Checkpoint: five-minute README flow succeeds, failure flow is actionable and visual evidence is
inspected.

### Phase 4: Release closure

- Task 10: add Linux packaging and Windows compatibility CI.
- Task 11: run one independent correctness, architecture and security review.
- Task 12: create public repository, push, verify CI, tag, Release, assets and contributors.
- Task 13: send the verified URLs and commands by Gmail.

## Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Synthetic degradation overpromises reality | High | Use scenario evidence and no universal score or certification |
| Detector-specific false confidence | High | Require two independent engines and report disagreement |
| Image bombs exhaust memory | High | File/frame/pixel caps before NumPy conversion |
| Quiet-zone estimate is wrong on rotated codes | Medium | Sample in QR-local coordinates, expose it as an estimate, test rotation |
| Heavy native dependencies complicate install | Medium | Use maintained wheels, OS matrix CI and clean-wheel smoke |
| CI passes but the Release is incomplete | High | Verify the public tag, Release page and expected wheel/sdist names |

## Open questions

None block v0.1. Future format and calibration-photo work remains outside this release.
